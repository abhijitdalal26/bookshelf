# Bookshelf

A personal 3D bookshelf web app for the owner's real book collection.
Design reference: https://layoffsandhires.com/engineering — a minimal, light-themed
"tape" of CSS-3D book spines you scroll along; hover reveals the cover; click opens details.

Claude is the sole developer on this project. Work from `TASKS.md` and update it as tasks finish.

## Layout

```
app\
  index.html   page shell (header, search, tabs, viewport, detail panel, reader overlay)
  shelf.css    all styles (light theme, mobile-responsive)
  shelf.js     shelf rendering, scroll/touch physics, interactions, book page
  reader.js    PDF.js reader: page/text modes, crop, highlights + notes, contents panel
  notes.js     highlight/note store (localStorage cache, synced via window.noteBackend)
  drive.js     book source + note backend: local server, or Google Drive on the hosted site
  config.js    hosted-site settings (Google OAuth client ID, Drive folder name)
  vercel.json  headers for the Vercel deploy (noindex, no-cache on generated data)
  books.js     GENERATED (window.BOOKS). Never hand-edit; rerun the scanner.
  covers.js    GENERATED by make-covers.py (cover image, aspect, spine colour per book)
  covers/      GENERATED cover JPEGs rendered from each PDF's first page
scripts\
  scan-books.js  scans D:\Books, enriches via Open Library, writes app\books.js
                 (has manual overrides for files that get wrong matches)
  make-covers.py renders covers from PDFs (PyMuPDF) into app/covers + app/covers.js
  serve.js       local server on port 8931: serves app + PDFs under /files/, notes at /api/notes
  upload-r2.js   uploads new/changed PDFs to the private R2 bucket `bookshelf` (wrangler)
worker\          Cloudflare Worker `bookshelf-files`: serves PDFs from R2 to the hosted site,
                 only for the owner's Google token (checked against tokeninfo + Drive about)
refs\            cloned reference repos, inspiration only, not used at runtime
TASKS.md         work queue and backlog
```

## Commands

- Rescan after adding/moving/removing books: `node scripts/scan-books.js` then `python scripts/make-covers.py`
- Run: `node scripts/serve.js` → http://localhost:8931 (PDFs at `/files/<path under D:\Books>`)
- Syntax check: `node --check app/shelf.js` (also reader.js, notes.js, drive.js) and `node --check scripts/serve.js`
- After a rescan, also `node scripts/upload-r2.js` so the hosted site can read the new books fast.
- Worker: `cd worker && npx wrangler deploy` (wrangler is logged in via OAuth).
- Deploy: `cd app && vercel deploy --prod` → https://readwithabhijit.vercel.app (also abhijit-bookshelf.vercel.app; project `bookshelf`).
  Deploys from the local folder (generated files are git-ignored), so redeploy after a rescan.

## Hosted site (Vercel)

- Public but `noindex`. Only the shelf (titles, covers, notes) is on Vercel. PDFs are read from
  Cloudflare R2 through the Worker (fast); any book not in R2 falls back to Drive. Opened pieces are
  kept in the browser's Cache Storage (`bookshelf-books-v1`), so reopening is instant.
- Reading needs Google sign-in (scopes: drive.readonly + drive.appdata). drive.js lists PDFs under
  `My Drive/Books` and matches them to `books.js` by path, then loads them with range requests.
- Highlights sync between devices via `notes.json` in the Drive app-data folder; locally they live
  in `data/notes.json` (git-ignored).

## Books folder (D:\Books)

- Each top-level folder is a collection tab; subfolders become "Parent / Child" tabs.
- Keep it tidy: no loose files in the root, no duplicates, folders named by topic.
  Rearranging files is fine when it improves the shelf — rescan afterwards and confirm
  the count and that every path in `books.js` still exists.

## Drive sync — ON

- User approved (2026-11-24). The Sync Drive button works; `POST /api/sync-drive` mirrors
  `D:\Books` to `J:\My Drive\Books` with robocopy, add/update only (no /PURGE, never deletes).
  Skips xsim and World History screenshots. Set `DISABLE_DRIVE_SYNC=1` to turn it off.
- The API is same-origin only (no CORS; cross-origin POSTs get 403).

## Per-book notes

`data/about-*.json` hold hand-written notes (about, kind, level, topics, readIf, takeaway) keyed by book path.
Run `node scripts/build-about.js` to merge them into the generated `app/about.js`.

## Conventions

- No build step, frameworks, or bundler. Plain HTML/CSS/JS.
- Light theme only: white bg, ink #0a0a0a, muted #666, hairline #e5e5e5, system sans.
- Books are CSS 3D: `.book > .face.spine + .face.cover` inside `#tape`. Each `.book` is
  placed every frame by JS (`perspective(2200px) translate3d … rotateY …`); sizes come from
  `--hpx` / `--ws` on `#tape` and `--dd` (cover width) per book. Shade via `--shade`.
- Spine structure must stay: `.band` (index) / `.st` (vertical title) / `.au` (vertical author).
- Don't use `<header>` inside overlays — the global `header` CSS would hit it.
- User-facing strings short and minimal, like the reference site.
- Accessibility: real buttons, aria labels, focus-visible outlines, `prefers-reduced-motion`
  respected in both CSS and the RAF physics.
- Ask before: custom cursor, dark mode, EPUB engine, self-hosting fonts.

## Interaction (matches the reference site)

The shelf is one continuous position (in books) easing to a target; the book passing the
centre turns its cover to face you while scrolling (smoothstep of its offset), neighbours part
around it. Wheel/drag move the target, then it snaps to a whole book. Hover lifts a spine and
tilts the centre cover; clicking a spine centres it; clicking the centre cover grows the book
page out of it (clip-path from the cover's rect, -4.5° tilt, text rises, cover inks in).
Escape / Back / ← Shelf fold it back into the cover. Open books are linked as `#<path>`.
The tape loops. Constants follow layoffsandhires.com/engineering's shelf.
